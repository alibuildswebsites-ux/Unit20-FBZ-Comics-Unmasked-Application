# Project Editing Rule — Read Before Edit

**Mandatory rule for every future implementation/edit in this project:**

1. Before changing any file, read the relevant current file(s), their tests, and the applicable assignment/research requirement.
2. Do not edit from memory, assumptions, or an earlier summary when the current file can be inspected.
3. Preflight the current state before making the change.
4. If anything fails, **stop implementation immediately**. Research the failure, reproduce it, identify the root cause, fix the underlying problem, run preflight again, and rerun the affected verification.
5. Do not declare a requirement complete because a script runs or a benchmark produces numbers. Completion requires evidence against the actual acceptance criterion.
6. After edits, run the relevant tests, real-dataset acceptance checks, document-generation checks, and final submission audit before claiming completion.
